# Development rules

- Keep commits small: one or two closely related changes per commit.
- Commit completed, meaningful changes as work progresses.
- Do not create empty commits or artificial edits to increase commit count.
- Use clear commit messages describing the actual change.
- Use the user's configured Git identity. Do not change global Git settings.
- Do not add Co-authored-by trailers or ChatGPT, OpenAI, Codex, or other AI attribution to commit messages or PR descriptions.
- Never commit credentials, datasets, participant videos, extracted participant features, model weights, or virtual environments.
- Never fabricate predictions, accuracy figures, or research results.
- Split data by participant before creating training and testing windows.
- Preserve existing work and never force-push.
